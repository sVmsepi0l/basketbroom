# Hogwarts integration: sprint 3

The closed pyramidion net is now **staged, saved and reloaded in both native Creator Kit maps**. The successful stage passed 164 native collision queries and exact unrelated-actor preservation checks; all 27 dungeon/anchor checks passed afterward. The corrected actual-Play check still needs a completed runtime result. The UE 5.8 standalone game remains a separate executable. This work does not establish a playable or published Hogwarts Legacy match, working dungeon travel, or Hogwarts multiplayer.

## Scope and preservation

[stage_hlck_pyramid_net.py](../Tools/stage_hlck_pyramid_net.py) uses the installed licensee UE 4.27 public editor APIs and the existing owned source importer. It accepts only the exact installed Phoenix project, the repo-mounted Basketbroom plugin, the active Basketbroom mod, a completed Asset Registry scan, no PIE worlds and no dirty packages. One of the two existing mod maps must already be open.

The complete write allowlist is seven native packages: `BB_Arena_Port.umap`, `Basketbroom_DungeonMap.umap`, four `SM_BB_Pyramid*` mesh assets and `M_BBPort_RoofNet.uasset`. Original OBJ sources provide the geometry. The helper does not call the whole arena builder, copy UE 5 packages, create a match Blueprint, change a DataTable or `ModEdits.sql`, register an entrance, or invoke travel.

The roof rises from the existing 138-foot eaves to a 207-foot apex. Its collision source has exactly five vertices and four triangular faces, with no horizontal base. Native mesh collision is double-sided and complex-as-simple; decorative cord/rib meshes have no collision. The existing native rebound physical material is reused.

For both maps, staging checks the original ownership marker and preserves every unrelated actor's identity, transform, tags, folder, mesh, material and collision setup. It also preserves the native default game mode, PlayerStart tag and dungeon exit fields/components. The lower rebound net retains its existing label and UObject name; the cosmetic rename was removed to preserve actor identity. Every overwritten package receives a verified byte backup outside shipping Content before authoring.

Before saving, and again after reloading each map, the helper queries the four roof faces, four hips and apex from both sides. The kit does not expose the UE 5 `HitResult.to_dict()` interface; these checks use the proven public hit/None profile trace contract, bracketing collision within one centimeter of each expected surface. Five additional queries prove the old flat eave opening remains clear. This is 41 actual collision queries per map per audit, not a physics/gameplay simulation.

A successful stage requires the final Content diff to remain inside the seven-package allowlist, installed map metadata and installed database hashes to remain unchanged, the registered entrance and saved SQL to match their prior values, the original editor map to be restored, and both dirty-package lists to be empty. Attempts have independent reports under `.local/hlck/pyramid-net-stage/<timestamp>/result.json`. `.local/hlck/pyramid-net-success.json` points only to a fully successful immutable result. A failed stage does not replace earlier successful evidence or discard unsaved editor work; its report identifies local backups for inspected recovery.

The read-only arena, dungeon and anchor inspectors recognize the amendment through an exact chain: original map hash, verified pre-stage byte backup, saved amended hash. They do not rewrite the September 12 arena/anchor receipts. The staged roof venue contains 905 generated arena actors, 18 original meshes and 19 port materials; the existing nine geometry checks and 27 complete dungeon/anchor checks remain mandatory, with the geometry roof check also running the actual collision audit.

## Execution sequence

1. Outside the editor, run `Mod/Tools/prepare_sources.py`, then `Tools/stage_hlck_pyramid_net.py --validate-sources`. Refresh the manifest again if rules or source art changed meanwhile.
2. Finish and close the standalone UE 5.8 editor before loading the memory-intensive kit. Launch the Creator Kit from the signed-in Epic Games Library, preserve the verified launcher authentication handoff and select the existing Basketbroom mod. Do not copy authentication arguments into files or start the unauthenticated UE4 executable.
3. Write a fresh harmless request before enabling the existing editor bridge. Open the saved owned dungeon through `load_hlck_dungeon.py` after its clean-editor checks. Run `stage_hlck_pyramid_net.py` with `{"dry_run": true}` and inspect its new result. Continue with `{"dry_run": false}` only when that exact preflight is ready.
4. Read the new successful receipt, then run `inspect_hlck_dungeon_anchors.py` on the restored dungeon. All 27 checks must pass with current map hashes and actual roof collision. Run `plan_hlck_dungeon_registration.py` to reverify the existing native registration without writing it again.
5. Inspect current shader-worker activity and available memory before ordinary Play. Preserve actual database bytes using the corrected observer's built-in preflight. Arm `test_hlck_dungeon_pie.py` through the bridge and use the normal editor Play button; this kit exposes no verified reflected true-Play starter, and Simulate is not an equivalent test.
6. Observe the corrected fixture and memory while it runs. It must identify the exact owned PIE world, native Phoenix game mode, game instance, player controller and possessed native character; then verify grounded spawn, runtime dungeon/subdivision extensions, existing entrance row, and exit interaction components/defaults. It gives startup at most ten minutes and an observed PIE world at most three minutes, ending only the owned session through public `editor_end_play()`. The root operator should end the owned session sooner if memory pressure or a shader backlog makes the bounded check unhealthy.
7. Verify no PIE world, callback or dirty package remains. The observer may identify a native dynamic-database cache refresh; inspect its retained pre-Play byte copies and report rather than restoring installed databases. Actual first entry and return still require a separate test through native interactions. No generic map-open command is treated as travel proof.
